### 09-1 [FIX] [P0] Redis settlement must never expose less than the final exposure to a concurrent admission
- **Where:** `crates/llm-proxy-store-redis/src/lib.rs` `RedisAdmissionBackend::settle_async` (about lines 222-270; `decr` of `reserved_key` at ~257, `incr` of `spent_key` at ~262; token window `decr`/`incr` at ~244-250). Reader side: `admit_budget` (INCR `reserved_key` then GET `spent_key`, ~420-440). Module doc "Atomicity model" (lines 14-30). Test server `crates/llm-proxy-store-redis/src/test_server.rs`. Also report items G2, rows 3 and 8.
- **Now:** Settlement releases the reservation (`DECRBY resv reserved_usd`) and only afterwards charges spend (`INCRBY spent charged`) as two separate awaited commands. An admission landing between them reads `reserved` without the released reservation and `spent` without the new charge, sees a budget with room, and is admitted. Total committed spend can exceed `usd_per_day` by one request. The token window has the same shape on a single key (`DECRBY` estimate, then `INCRBY` usage). The module doc argues over-admission is impossible but only covers admit-vs-admit. Postgres does both steps in one transaction, so only Redis is affected.
- **Wanted:** Plan done-when: "two instances sharing replica stores enforce one budget". A settle running concurrently with admissions must never make the combined `spent + reserved` that an admission can observe drop below its final value.
- **How (decision made: ordering plus one net command, no Lua).** Reason: Redis cannot make two keys atomic without Lua or MULTI, and the existing `if exists { decr }` guards cannot be expressed inside MULTI. The admission side reads `reserved` (the INCR reply) strictly before it reads `spent`. So if settlement writes `spent` first and releases `reserved` second, every interleaving shows an exposure that is greater than or equal to the final one. The error direction is a briefly stricter budget, which matches the module's fail-closed stance.
  1. In `settle_async`, keep the lease claim, then reorder money: first `INCRBY spent_key charged` (+ `EXPIRE DAY_TTL`) when `charged_usd` is `Some`, then `DECRBY reserved_key reserved_usd` guarded by `exists` as today. Add a comment stating the invariant ("spent is charged before the reservation is released so a concurrent admission can only over-count").
  2. Token window: replace the `exists`+`decr` then `incr` pair by one command. Compute `exists` first, then `delta = usage_tokens.unwrap_or(0) as i64 - (if key_existed { reserved_tokens as i64 } else { 0 })`, and issue a single `INCRBY token_key delta` (skip when `delta == 0` and the key is absent; keep the `EXPIRE MINUTE_TTL` after charging). Behaviour must stay equal to today for every combination of (key present/absent, usage present/absent).
  3. Make the lease claim exclusive: today `settle_async` does `GET` then `DEL` and ignores the DEL count, so two concurrent settles of one lease both release counters. Use `let removed: i64 = conn.del(&record_key).await?; if removed == 0 { return Ok(()); }` (the test server's `DEL` already returns the removed count).
  4. Update the module doc "Atomicity model" to describe settle ordering and say that settle-vs-admit is covered by ordering, not by a transaction.
- **Shared test-server extensions (do once, used by 09-1, 09-2, 09-3).** The server (`handle()` in `test_server.rs`) supports only `PING AUTH SELECT CLIENT COMMAND HELLO(error) GET SET DEL EXISTS EXPIRE SETEX INCR DECR INCRBY DECRBY SADD SMEMBERS XADD`. It has no `EVAL`, `EVALSHA`, `MULTI`, `EXEC`, `ZADD`, `ZREM`, `ZRANGEBYSCORE`. Connection threads are a fixed pool of 4 (`for _ in 0..4`), so more than four simultaneously open store connections will hang a test; keep each test to at most two `RedisStore`s.
  - Add `TestRedis::start_trace()` and `TestRedis::take_trace() -> Vec<std::collections::BTreeMap<String, String>>`. When tracing is on, after every mutating command (`SET SETEX DEL EXPIRE INCR* DECR* EVAL ZADD ZREM`) push a snapshot of the live string keys (expired keys excluded). Store the trace in a new `Db` field `trace: Mutex<Option<Vec<...>>>`. This lets tests assert on every state a concurrent reader could observe.
  - Use `.get()`/slice patterns, not indexing, in the new code (see Rule violations).
- **Test:** new test in `crates/llm-proxy-store-redis/tests/replica_state.rs`, name `settlement_never_lets_a_concurrent_admission_see_less_exposure_than_the_final_state`.
  - Setup: `TestRedis::start()`, `RedisStore::connect(url, "p1")`, `replica_admission(budgeted("1"), pricing(), caps, store)` as in `two_instances_sharing_the_store_enforce_one_budget_between_them` (line 81). Admit one claim through `Admission::reserve` and keep its lease (hold the `AdmissionOutcome`/lease the existing tests hold). Compute the key names `p1:ad:spent:key:<YYYYMMDD>` and `p1:ad:resv:key:<YYYYMMDD>` (see `spent_key`/`reserved_key`; day from `OffsetDateTime::now_utc()` via the same `day_stamp` format).
  - Call `server.start_trace()`, then `backend.settle_async(&lease, &Settlement{ charged_usd: Some(c), usage_tokens: Some(t), now, .. })` directly (it is public) for two parameter sets: charged greater than the reserved estimate, and charged smaller. Then `take_trace()`.
  - Assertion: let `exposure(snapshot) = parse(spent_key) + parse(resv_key)` (missing key = 0). For every snapshot in the trace, `exposure(snapshot) >= exposure(last snapshot)`. Same for the token key when `tpm` is set: every snapshot's value `>=` the final value.
  - Fails before the fix: after the old `DECRBY resv` snapshot, exposure equals `reserved_before - r` which is below the final `spent + charged + (reserved_before - r)` whenever `charged > 0`. Passes after the reorder.
  - Second test `a_lease_settled_twice_releases_its_counters_once`: reserve one claim, call `settle_async` twice concurrently with `tokio::join!`; assert the reserved key equals 0 (not negative) and the in-flight slot key equals 0 via `server.get(...)`.

### 09-2 [FIX] [P0] Redis unsettled leases must actually release their reservation (crash bound is currently false)

The `RedisAdmissionBackend` handle used by `replica_admission_over_config` is built inside the store crate, so add a `pub fn spawn_reaper(store: RedisStore) -> tokio::task::JoinHandle<()>` in the store crate instead and call that from `redis_replica` (keeps the app thin and testable).   6. Update the module doc (lines 25-28) to describe: lease record plus deadline index plus reaper; delete the "expire on a TTL" sentence.
